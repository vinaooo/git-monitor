# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Git Monitor (code name and package: `painel`; app ID `io.github.vina.Painel`): GNOME/GTK4 + libadwaita app (Python/PyGObject, meson, Flatpak) showing one card per GitHub/GitLab repo: open issues, pending PRs/MRs, CI state, open-in-browser. No third-party Python deps (stdlib `urllib` only).

## Commands

- Tests (stdlib `unittest`, no deps; write the failing test first): `python3 -m unittest discover -s tests -t .`; single: `python3 -m unittest tests.test_gitlab.GitLabTest.test_counts_and_name`
- Run from source (no tree-run support, must install to a prefix):
  ```
  meson setup build --prefix=$PWD/_prefix && meson install -C build
  GSETTINGS_SCHEMA_DIR=_prefix/share/glib-2.0/schemas XDG_DATA_DIRS=_prefix/share:/usr/share _prefix/bin/painel
  ```
- Flatpak: `flatpak-builder --user --install --force-clean build-flatpak io.github.vina.Painel.yml`, then `flatpak run io.github.vina.Painel`
- Lint: `desktop-file-validate data/*.desktop`, `appstreamcli validate --no-net data/*.metainfo.xml`
- `build/`, `_prefix/`, `build-flatpak/`, `.flatpak-builder/` are throwaway; delete after use.

## Architecture

Package `painel/` (installed to `<prefix>/share/painel/painel/`; new modules must be added to `painel/meson.build`). Launcher template: `src/painel.in`. Dependencies point inward: UI -> `service` -> providers -> `HttpClient` port; only `tokens.py` and the UI import GTK/libsecret, so everything else is unit-testable with `tests/fakes.py:FakeHttp`.

- `repo_id.py` — repo identity string `host/path` (`github.com/o/r`, `gitlab.com/g/sub/p`): `parse` (bare `o/r` = GitHub; GitLab only for `gitlab.com` / `gitlab.*`), `migrate` (legacy bare `o/r` entries), `host_of`.
- `status.py` — `RepoStatus` frozen dataclass; the only shape UI consumes. CI vocabulary: `success|failure|running|cancelled|none`.
- `http.py` — `HttpClient` port, `UrllibClient`, `HttpError(code)`, `NetworkError`. Redirects to another host strip `Authorization`/`PRIVATE-TOKEN` (urllib forwards them by default); keep that when touching the client.
- `github.py` / `gitlab.py` — `fetch(path, token) -> RepoStatus`, raise on failure. Deliberate quirks: GitHub `open_issues_count` includes PRs (issues = count - PRs, PR count from search API); GitLab project payload omits the issue count when anonymous (use `/issues_statistics`), MR count is the `X-Total` header, GitLab statuses mapped in `_CI`.
- `service.py` — `StatusService`: host -> provider, converts every failure into `RepoStatus(error=...)`. Add a provider = new module + branch in `_provider` + tests.
- `tokens.py` — `TokenStore` (libsecret, keyed by `host`; legacy `purpose=github-token` fallback). Never store tokens in GSettings/files; keyring failures raise `TokenStoreError` (no plaintext fallback).
- `groups.py` — pure `Groups` model (ordered named groups, each repo in exactly one; persistence injected like `TitleStore`). GSettings `groups` (`a(sas)`) is the source of truth; legacy flat `repos` is only migrated into group "General" on first run.
- `health.py` / `chips.py` / `style.py` — pure CI + PR/MR health: `summarize_ci` (latest run per workflow/pipeline key + runs in progress elsewhere), PR/MR buckets (draft > changes > failing > conflict > approved > waiting; GitHub via GraphQL node, GitLab via `detailed_merge_status`), `severity` (error > warning > accent > success > none) drives the card's left stripe; `chips_for(status)` is what the card renders; PR/MR chips carry a `url` (`pr_list_url`: GitHub search filters, GitLab only draft/open filters) and the card makes them clickable. Colors are semantic Adwaita ones (running/waiting use fixed `@blue_*` because the user's accent may be gray); never encode state by color alone (glyph + word). GitHub review states need a token (GraphQL), anonymous gets `pr_detail=False`; GitLab running pipelines are listed, not counted via `X-Total` (that 500s on huge projects). Chips use a capped `Gtk.FlowBox` (not `Adw.WrapBox`) so cards stay narrow enough for grid columns. To eyeball UI headlessly, render a window with `WidgetPaintable` -> `Gtk.Snapshot` -> `renderer.render_texture(...).save_to_png`.
- `importer.py` / `sources.py` / `import_dialog.py` — "Import from account…" (menu item, prototype entry point): `repo_id.parse_account` -> provider `list_repos(account, token) -> ([RepoInfo], truncated)` (GitHub: own account + token = `/user/repos` incl. private, else org then user; GitLab: user id then group with subgroups; both paginated, capped at 10 pages) -> `StatusService.list_repos` -> pure `importer.plan` (forks/archived opt-in, dedupe against tracked repos; `default_selection` = what the dialog's picker pre-ticks) -> `Window.import_account` (group named `importer.group_name(account)`, reused if it exists). `SourceStore` (GSettings `sources`, `a(sssasas)`) remembers each imported group's account, kinds and every repo seen (`known`); with `sync-imported` on, `Window._sync_sources` re-lists every 30 min and adds only repos not in `known`, so a card the user removed is never resurrected. `sync-asked` records the one-time first-import question. The import dialog lists every repo with a checkbox (`Adw.ExpanderRow`, kinds switches re-tick only their kind); `SourceStore.known` gets **all** listed repos, chosen or not, so sync never adds the ones skipped.
- `intervals.py` / `interval_row.py` / `group_settings.py` — per-group refresh interval (GSettings `group-intervals` `a{si}`, absent = global `refresh-seconds`). `Window.restart_timers` runs one `GLib` timer per group (rebuilt on group create/rename/delete, interval change, import); a tick refreshes only its own group, and only if it is visible or `refresh-all-groups` is on. `IntervalRows` (switch + spin + rate-limit warning/suggestion) is shared by the "Group settings…" dialog and the import dialog; `rate_limit.github_warning_groups` sums the load over groups and `min_interval` suggests a fitting interval; Preferences' estimate uses each group's own interval. Private repos appear only when a token for that host is stored.
- `search.py` — pure `matches(query, ident, title, status)` for the header search (Ctrl+F; a `Gtk.SearchEntry` in a sliding `Gtk.Revealer` next to the header button): every word must occur in ident/URL/title/CI+PR words ("passing", "waiting", "ready"…; bucket keys as in `chips.py`). `Window._refilter` filters every `GroupPage` (`set_filter`, "No Matches" page) and puts `Name (n)` in the sidebar row title while a query is set (group identity is `page.get_child().name`, never the title); re-run from `_apply_sort`. While a query is set a `Gtk.Stack` (`Window.body`) shows `Window._fill_results` — one list of every match across groups (title, group · ident, CI/PR words; click = jump to that group, close the search, `GroupPage.reveal` glides the scroll to the card and `Window._blink` flashes `.search-hit`); picking a group in the sidebar drills into its filtered page. Drag is off while searching.
- `virtual.py` — pure virtual-group table (`DEFINITIONS`: github, gitlab, ready, cancelled, ci-failing, attention, waiting, errors; `members`, `shown`). GSettings `virtual-disabled` (`as`) lists switched-off ids (Preferences switches), so new definitions default on. `Window._sync_virtual` (debounced via `_schedule_virtual`, called from `_apply_sort`, `_drop_repo` and the setting) keeps a second hidden `Adw.TabView` (`vtab_view`, body stack child `'virtual'`) with one `GroupPage` per non-empty enabled group; each holds **mirror cards** (separate `Card` instances in `Window.mirrors`, fed by `_apply`, `can_drag` off) because a widget has one parent. Sidebar: second `ListView` under the groups, a primary-click gesture on each row drives `_show_real` / `_show_virtual` (never `single_click_activate`: GTK also selects rows on hover then) (`virtual_active`; `dim-selection` keeps one row looking selected; never use the vtab's own `selected-page` notify, it auto-selects on first insert). Group rename/delete/settings are disabled while one is open; `refresh()` then refreshes the member repos. Status-based groups only see repos already refreshed.
- `icons.py` / `icon_picker.py` — group icons: pure `IconStore` (GSettings `group-icons` `a{ss}`, default `folder-symbolic` is not stored; renamed/removed with the group like `IntervalStore`) and `CHOICES`, the Adwaita symbolic icons offered by `IconPicker` (a `Gtk.FlowBox` of toggle buttons) in the New group dialog and Group settings. Sidebar rows show the icon left of the name (`Window.sidebar_icons`); virtual groups carry a fixed `Definition.icon` (GitHub/GitLab logos are `data/painel-github-symbolic.svg` / `painel-gitlab-symbolic.svg`, Simple Icons, CC0).
- `notify.py` — pure CI-transition detection for desktop notifications: `step(entry, ci) -> (entry, kind)` (kinds `failed|recovered|broke_running`; `settled` remembers the last success/failure so a running phase between two results hides nothing; first sight of a repo returns kind `None`), `wanted`, `ci_url`, `StateStore` (JSON `$XDG_DATA_HOME/painel/ci-state.json`, atomic write, corrupt = empty; deliberately not GSettings so changes while closed are reported next launch). `Window._notify_ci` (called from `_apply`, skips errors) always advances the state, even when notifications are off or the group is muted, so re-enabling never floods; max 5 per refresh pass, the rest one summary. Notification click = `app.open-card` (focuses the card via `Window.open_card`), button = `app.open-ci` (both in `main.py`, target `s`). GSettings `notify-ci` (default on), `notify-kinds` (`as`), `notify-muted` (`as`, group names; carried on rename, dropped on delete).
- `background.py` / `search_provider.py` — GSettings `run-in-background` (default off): `App._sync_background` holds the app so `Window._on_close_request` only hides the window (timers + CI notifications keep running; `_tick` refreshes every group while hidden) and calls the Background portal through a raw `Gio.DBusProxy` (no libportal GI namespace; `options()` is the pure part, errors only logged). A hidden window is not `active_window`: use `App.window()`. `search_provider.register` exports `org.gnome.Shell.SearchProvider2` at `/io/github/vina/Painel/SearchProvider` from `App.do_dbus_register`; pure `find` reuses `search.matches` (leading "painel" ignored, max 20); items come from `Window.cards`, so results are empty until a window exists. Needs `data/*.search-provider.ini`, `data/*.service.in` (D-Bus activation) and `DBusActivatable=true` in the .desktop; the Shell may need a re-login to notice the .ini. No new Flatpak finish-args.
- `sorting.py` — pure `sorted_order(order, mode, reverse, info)` for the header's view/sort menu (modes manual|name|issues|prs|ci ("Health" in the menu); repos without data go last). `Window._apply_sort` re-sorts after every refresh result, so order is live; while a sort mode is active in-group drag-reorder is disabled (`GroupPage.can_reorder`). GSettings `sort`, `sort-reverse`, `view` (grid-small|medium|large|list; list = `Card.set_compact`) drive stateful `win.*` actions via `Settings.create_action`.
- `group_page.py` — `GroupPage`: one group's FlowBox, Slots, `FlipAnimator` and the live drag-reorder preview (blank slot for the dragged card; never reparent the drag source mid-drag, re-sequence the others).
- Real drag-and-drop can be tested without touching your session: `tools/headless-gnome/dnd-test.sh` starts an isolated headless GNOME Shell (own D-Bus *and* own `XDG_RUNTIME_DIR`) and injects pointer events through Mutter's RemoteDesktop D-Bus API; prints `RESULT OK`. Never run the nested shell with the real runtime dir: its xdg-document-portal unmounts `/run/user/$UID/doc` and breaks `flatpak run` (fix: `systemctl --user restart xdg-document-portal.service`). Drag bugs that signal-emitting headless tests miss show up here (e.g. `get_child_at_pos` returning a nested chip FlowBox child).
- `motion.py` — FLIP animation: `Slot` paints a card displaced, `FlipAnimator` measures layout before/after in the frame-clock `layout` phase.
- `window.py` — Files-style layout: `Adw.OverlaySplitView` whose sidebar pane (own header bar + group list + bottom new-group button) spans the full window height and whose content pane has its own header (title = current group). One `Adw.TabView` (page per group, no visible tab bar: it is the model and the content stack) is the single source of UI truth; the sidebar is a `Gtk.ListView` over `tab_view.get_pages()` inside `Adw.OverlaySplitView` (collapsed under 600sp: header toggle opens it as an overlay). Handles group actions, cross-group moves (`move_to_group`, deferred with `idle_add` so the drag source is moved after the drag ends; drop targets: sidebar rows, card right-click menu), shared `cards` dict, refresh (only the selected group, and again whenever the selection changes, unless the `refresh-all-groups` preference is on: then every group each cycle and no extra refresh on switch; one daemon thread per repo, results via `GLib.idle_add`). `card.py`/`prefs.py`/`main.py` — card UI (hover pencil rename, drag source, group menu), preferences (interval, layout, per-host tokens), app + dependency injection. Group health tint: with `refresh-all-groups` on, `Window._update_marks` stores `health.group_severity` in each `Adw.TabPage` `keyword` (abused as a carrier); sidebar rows tint their `row` widget on `notify::keyword` and show the mark icons. Colors are `row.tint-*` rules in `style.py` (preference key `colored-tabs`, shown as "Colored group rows"; the key name is kept so saved values survive). Don't touch a ListView row's parent while binding (not parented yet: GTK criticals), defer with `idle_add`. GSettings keys: `groups`, `layout`, `titles` (`a{ss}`, custom titles via `titles.py:TitleStore`), `refresh-seconds`, legacy `repos`.

Flatpak finish-args include `--filesystem=xdg-config/gtk-4.0:ro` so libadwaita picks up the user's custom `~/.config/gtk-4.0/gtk.css` theme (sandbox `XDG_CONFIG_HOME` differs from the host's); Flathub review may question it.
